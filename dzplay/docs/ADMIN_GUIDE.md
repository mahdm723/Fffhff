# دليل المشرف — DZPLAY (V3 + V4)

كل الأوامر تُنفَّذ في الخادم داخل مجلد التطبيق:

```bash
cd /opt/dzplay/dzplay
```

---

## 1. أول حساب مشرف وتفعيل التحقق بخطوتين (2FA)

1. أنشئ الحساب (مرة واحدة):
   ```bash
   docker compose exec app python -m app.admin_cli create-admin owner
   ```
   يطلب كلمة مرور من 12 حرفًا على الأقل، ثم يعرض **رمز QR** في الطرفية.
2. افتح **Google Authenticator** أو **Microsoft Authenticator** على هاتفك، ثم «إضافة حساب» ← «مسح رمز QR». إن لم يظهر الرمز جيدًا في الطرفية، أدخل المفتاح النصي المعروض تحته يدويًا.
3. اعرف عنوان اللوحة السري:
   ```bash
   grep ADMIN_PATH .env
   ```
   افتح `https://<نطاقك><ADMIN_PATH>`، مثلًا `https://72-61-147-28.sslip.io/panel-3f9c…`.
4. ادخل باسم المشرف وكلمة المرور والرمز ذي 6 أرقام من التطبيق.

**مهم:**
- لا يوجد رابط للوحة داخل التطبيق، و`/admin` لا يعمل.
- لا تشارك `ADMIN_PATH`.
- الجلسة تنتهي بعد 30 دقيقة دون نشاط، أو بعد 12 ساعة في كل الأحوال.
- 5 محاولات دخول خاطئة تقفل الدخول من شبكتك لمدة 15 دقيقة.

| الحالة | الأمر |
|---|---|
| فقدت الهاتف أو تطبيق المصادقة | `docker compose exec app python -m app.admin_cli reset-admin-2fa owner` (يعرض QR جديدًا) |
| نسيت كلمة المرور | `docker compose exec app python -m app.admin_cli set-admin-password owner` |
| مشرف إضافي | `docker compose exec app python -m app.admin_cli create-admin اسم_آخر` |
| سجل الإدارة + فحص سلامته | `docker compose exec app python -m app.admin_cli audit` |
| (اختياري) قصر اللوحة على شبكتك | في `.env`: `ADMIN_IP_ALLOWLIST=1.2.3.4` أو `1.2.3.0/24`، ثم `docker compose up -d app` |

## 3. التحكم في التفاعل ومكتبة التعليقات

### القواعد الثابتة
- الإعجابات الحقيقية لا تُلمس أبدًا. التعزيز يُحفظ في حقل منفصل، و**الرقم الظاهر = الحقيقي + المضاف**، ولا يقل عن صفر.
- اللوحة تعرض الرقمين منفصلين، مثلًا `👍 120 = 0 + 120`.
- إجمالي «إعجابات أفكاري» في ملف المستخدم يستخدم الرقم الظاهر.
- لا تُنشأ تفاعلات وهمية بأسماء مستخدمين.
- التعليقات تُنشر من **حسابات نظام** تظهر باسم «dzplay»، أو من الحساب الرسمي بشارة «DZPLAY الرسمي». هذه الحسابات لا تدخل في المطابقة ولا في الإحصائيات ولا تستطيع تسجيل الدخول.
- **على الأفكار**: يصل التعليق لصاحب الفكرة فقط، مثل أي تعليق. **على Reels**: يظهر للجميع.
- لا يتكرر نفس النص على نفس المنشور أبدًا، حتى عبر عمليات مختلفة.
- سياسة الخصوصية تذكر أن الفريق قد يضيف تفاعلات وتعليقات لتنشيط المحتوى.

### تعزيز الإعجابات / عدم الإعجاب
1. **المحتوى** ← علّم منشورًا أو أكثر ← **تعزيز التفاعل**. أو الصق المعرّفات مباشرة في **التفاعل ← تعزيز**؛ يُقبل أيضًا رقم Reel القصير الذي يعرضه البوت.
2. اختر العملية:
   - **إضافة عدد**: +N، ويمكن إدخال سالب للإنقاص.
   - **تحديد الرقم الظاهر**: يصبح الرقم الظاهر N بالضبط.
3. اختر التوقيت:
   - **فوري**.
   - **تدريجي**: مدة بالدقائق أو الساعات أو الأيام. تتوزع الزيادة بالتساوي، وتُطبَّق كل `ENGAGEMENT_TICK_SECONDS` (60 ثانية افتراضيًا).
4. **تطبيق**. العمليات التدريجية تظهر في **العمليات** مع شريط تقدم وزر **إلغاء**. ما طُبِّق قبل الإلغاء يبقى.

### التعليقات
1. اختر المنشورات (كما في التعزيز) ← **التفاعل ← تعليقات**.
2. اختر المصدر:
   - **من المكتبة**: علّم تعليقات بعينها.
   - **عشوائي من تصنيف**: عدد التعليقات لكل منشور، وتُختار مختلفة لكل منشور.
   - **نص جديد**.
3. الظهور: **dzplay** (الافتراضي) أو **DZPLAY الرسمي**.
4. فوري، أو تدريجي موزّع على مدة.

### المكتبة (التفاعل ← المكتبة)
- **التصنيفات**: الافتراضية ترحيب وتشجيع ودعم وتفاعل ودعابة وشكر وأخرى. يمكن إضافة تصنيف أو إعادة تسميته أو حذفه إن كان فارغًا.
- **تعليق جديد**، تعديل، حذف، بحث.
- **العدّاد**: يبيّن كم مرة استُخدم كل تعليق.
- **استيراد دفعة**: الصق تعليقًا في كل سطر. الأسطر الفارغة والمكررة داخل نفس التصنيف تُتخطى. الحد حوالي 1000 تعليق في كل استيراد.

### الحدود (قابلة للتعديل في `.env`)

| المتغير | الافتراضي | المعنى |
|---|---|---|
| `ENGAGEMENT_MAX_TARGETS` | 200 | عدد المنشورات في العملية الواحدة |
| `ENGAGEMENT_MAX_AMOUNT` | 1,000,000 | أقصى عدد لكل منشور ومقياس |
| `ENGAGEMENT_MAX_COMMENTS` | 200 | تعليقات لكل منشور في العملية |
| `ENGAGEMENT_MAX_DURATION_HOURS` | 720 | أقصى مدة للعملية التدريجية (30 يومًا) |
| `SYSTEM_ACCOUNTS` | 25 | عدد حسابات النظام التي تُنشر منها التعليقات |

## 4. بوت Telegram (رفع Reels واستعادة كلمات المرور)

**من لوحة التحكم (الأسهل):**
1. في Telegram:
   - افتح @BotFather وانسخ رمز بوتك. إذا شاركته مع أحد، اضغط **Revoke** وخذ رمزًا جديدًا.
   - أرسل أي رسالة إلى @userinfobot وانسخ رقمك (Id).
   - افتح بوتك واضغط **Start**.
2. اللوحة ← **الأمان والنظام** ← **بوت Telegram**:
   - الصق الرمز ورقم المحادثة.
   - اكتب رمز التحقق من تطبيق المصادقة.
   - اضغط **حفظ وربط البوت**.
3. تصلك رسالة «✅ DZPLAY متصل»، والربط فوري دون إعادة تشغيل.

ما يحدث عند الحفظ:
- يُحفظ الرمز في قاعدة البيانات **مشفّرًا**، ولا يُعرض مرة أخرى؛ تظهر آخر 4 أحرف منه فقط.
- يُطلب رمز 2FA عند كل تغيير.
- يُسجَّل التغيير في سجل الإدارة.
- قيمة اللوحة تتقدم على `.env`. زر **إزالة الربط** يعيدك إلى إعداد `.env` إن وُجد.

**بديل من الخادم:** `sudo deploy/telegram-setup.sh` يسألك عن الرمز (مخفيًا) ورقم المحادثة، ثم يربط البوت ويرسل رسالة تجربة. أو ضع `TELEGRAM_BOT_TOKEN` و`TELEGRAM_ADMIN_CHAT_ID` في `.env`، ثم نفّذ `docker compose up -d app`.

**الاستعمال داخل Telegram:**
   - أرسل فيديو أو صورة أو ألبومًا مع وصف، فيصبح Reel.
   - الأوامر: `/list` و`/hide` و`/show` و`/delete` و`/pin <id> [ساعات]` و`/unpin` و`/caption` و`/stats` و`/help`.
   - يعمل البوت فقط في محادثتك (`TELEGRAM_ADMIN_CHAT_ID`)، وأي محادثة أخرى تُتجاهل.
   - الحد 20MB لكل ملف (قيد Telegram).

**استعادة كلمة المرور:** رابط «نسيت كلمة المرور؟» يظهر في صفحة الدخول بمجرد ربط البوت. توجد طريقتان لإيصال الرمز:

- **يدويًا (بدون أي إعداد إضافي):**
  1. يطلب المستخدم الاستعادة، فتصلك رسالة في البوت فيها بريده ورقم الطلب.
  2. اضغط **🎲 توليد رمز**، فيظهر لك الرمز مع البريد.
  3. أرسله أنت إلى المستخدم من بريدك (Gmail مثلًا).
  4. يكتبه المستخدم في التطبيق ويختار كلمة مرور جديدة، وتُغلق كل جلساته القديمة.
- **تلقائيًا بالبريد:**
  1. اللوحة ← **الأمان والنظام** ← **البريد** ← زر **إعداد Gmail**.
  2. اكتب بريدك، و«كلمة مرور التطبيقات» من Google. لإنشائها: حساب Google ← الأمان ← فعّل التحقق بخطوتين ← **App passwords** ← أنشئ واحدة واسمها DZPLAY.
  3. أدخل رمز التحقق ← **حفظ وإرسال بريد تجربة**.
  4. من بعدها، زر «توليد رمز وإرساله» في البوت يرسل الرمز للمستخدم مباشرة.

كلمة مرور البريد تُحفظ مشفّرة ولا تُعرض بعد الحفظ. البديل: متغيرات `SMTP_*` في `.env`.

## 5. النسخ الاحتياطي

- المثبّت يضبط نسخة **يومية مشفّرة** الساعة 03:17 في `/var/backups/dzplay`، ويحتفظ بآخر 14 نسخة.
- كل نسخة تحتوي قاعدة البيانات و`.env`، مشفّرة بـ AES-256 بكلمة السر `BACKUP_PASSPHRASE`.
- **انسخ كلمة السر إلى مكان آمن خارج الخادم:** `grep BACKUP_PASSPHRASE .env`. بدونها لا يمكن فك أي نسخة.

```bash
sudo deploy/backup.sh                                     # نسخة الآن
ls -lh /var/backups/dzplay                                # النسخ الموجودة
sudo deploy/restore.sh /var/backups/dzplay/dzplay-….tar.gpg              # استعادة (يطلب كتابة RESTORE)
sudo deploy/restore.sh FILE --with-env                    # على خادم جديد: يستعيد .env أيضًا
tail /var/log/dzplay-backup.log                           # سجل النسخ اليومي
```

- **نسخة خارج الخادم (موصى بها):** ثبّت rclone وأعدّه بالأمر `rclone config`، ثم ضع في `.env`: `BACKUP_RCLONE_REMOTE=اسم:مجلد`.
- **ما لا يُنسخ:** ملفات الفيديو والصور المؤقتة، لأن أصلها محفوظ في Telegram ويُعاد تنزيله تلقائيًا.

## 6. تحصين الخادم

```bash
sudo deploy/harden.sh                 # جدار ناري (SSH + 80 + 443 فقط)، fail2ban، تحديثات أمنية تلقائية
sudo deploy/harden.sh --ssh-keys-only # بعد إضافة مفتاح SSH: إيقاف الدخول بكلمة المرور
sudo ufw status verbose
sudo fail2ban-client status sshd
```

`--ssh-keys-only` لا يوقف كلمة المرور إذا لم يجد مفتاح SSH مسجّلًا، حتى لا تُقفل خارج خادمك.

## 7. المتغيرات الجديدة في `.env` (V3)

القائمة الكاملة مع القيم الافتراضية والشرح في `.env.example` (قسم «V3»). الأهم:

| المتغير | ملاحظة |
|---|---|
| `ADMIN_PATH` | مسار اللوحة السري (يولَّد تلقائيًا) |

| `SMTP_*` | بريد رموز الاستعادة |
| `MEDIA_CACHE_MAX_GB` / `MEDIA_CACHE_TTL` | ذاكرة الوسائط: 5GB / 14 يومًا |
| `VIDEO_*` / `IMAGE_*` | جودة المعالجة |

| `SYSTEM_ACCOUNTS` / `ENGAGEMENT_*` | التحكم في التفاعل |

# V4 — الأسماء، البحث، الرسائل المباشرة، المكالمات، تطبيق أندرويد

## 9. ما الجديد للمستخدمين

- **الاسم الظاهر:** الافتراضي `dzplay`. من 3 إلى 20 حرفًا (عربي، لاتيني، أرقام، مسافة، `_`). تُرفض الأحرف الخفية واتجاه الكتابة المعكوس والأحرف المتشابهة والأسماء المحجوزة (admin، الإدارة، dzplay…) والكلمات المسيئة. يمكن تغييره مرة كل 14 يومًا، والعودة إلى dzplay مسموحة دائمًا. **سجل الأسماء يظهر في لوحة الإدارة فقط** (صفحة المستخدم ← «سجل الأسماء»).
- **المعرّف العام `DZ-XXXXXX`:** عشوائي وثابت ومستقل عن المعرّف الداخلي، وله زر نسخ في «حسابي». حصل عليه كل مستخدم قديم تلقائيًا.
- **الجنس و18+:** إلزاميان عند التسجيل، بالبريد أو بـ Google. المستخدمون القدامى يُسألون عن الجنس مرة واحدة بلطف، ويؤكدون 18+ مرة واحدة قبل الرسائل المباشرة والمكالمات.
- **أين يظهر الاسم:** في الأفكار وتعليقات Reels والملف والمحادثات المباشرة. **الرسائل العشوائية تبقى dzplay** حتى يضغط الشخص بنفسه «كشف هويتي». الكشف من طرف واحد ولا يمكن التراجع عنه، وتظهر رسالة نظام في المحادثة.
- **البحث (في «حسابي» فقط):** بالمعرّف الكامل أو بجزء من الاسم (حرفان على الأقل، مع توحيد أ/إ/آ وة/ه وى/ي). أصحاب الاسم dzplay يُعثر عليهم بالمعرّف فقط. لا يظهر بريد أبدًا. البحث وفتح المعرّفات محدودان: 20 في الدقيقة و300 في اليوم.
- **الرسائل المباشرة وطلبات المراسلة:** محادثة واحدة لكل شخصين. أول رسالة تصل كطلب في تبويب «طلبات الرسائل» (قبول / تجاهل / حظر)، وللمرسل 3 رسائل كحد أقصى حتى يرد الطرف الآخر. التجاهل لا يُبلَّغ للمرسل.
- **الخصوصية والتواصل («حسابي»):** يمكن إيقاف كل واحد مما يلي، ويُطبَّق المنع في الخادم:
  - استقبال الرسائل المجهولة (يبقى الإرسال ممكنًا)؛
  - استقبال الرسائل المباشرة؛
  - استقبال المكالمات؛
  - الظهور في البحث بالاسم.

## 10. المكالمات الصوتية والمرئية

- **متى تتاح:** تظهر الأزرار في رأس المحادثة، وتعمل فقط بعد أن يرد الطرف الآخر مرة واحدة على الأقل. يتحقق الخادم قبل كل مكالمة من:
  - العضوية في المحادثة؛
  - عدم وجود حظر؛
  - أن المستقبِل يقبل المكالمات؛
  - أن الحسابين نشطان؛
  - أن الطرفين أكّدا 18+.
- **قيود:** مكالمة واحدة لكل مستخدم (ويسمع المتصل الآخر «مشغول»). بعد 3 مكالمات متتالية لم يُرد عليها يجب الانتظار 30 دقيقة، وأقصى عدد 20 مكالمة في الساعة. الحظر أو الإيقاف أو الحذف ينهي المكالمة فورًا.
- **الخصوصية:** كل الوسائط تمر عبر خادم TURN الخاص بك (coturn) في وضع relay فقط، فلا يرى أي طرف عنوان IP الآخر. يحذف الخادم أيضًا أي مرشح غير relay ويمسح العنوان المرجعي `raddr`. التشفير DTLS-SRTP من طرف إلى طرف، و**لا تُسجَّل المكالمات أبدًا**. يُحفظ فقط: من اتصل بمن، ومتى، والمدة، والجودة (RTT والفقد ومعدل البت). يُحذف هذا السجل بعد 90 يومًا (`CALL_LOG_RETENTION_DAYS`).
- **في اللوحة:** المحتوى ← «المكالمات». يعرض إحصاءات 7 أيام (النتائج، الدقائق، متوسط RTT والفقد ومعدل البت، والتحقق من «عبر TURN فقط»)، وسجل كل مكالمة. البلاغات عن المكالمات تظهر في «البلاغات» مرتبطة بالمكالمة.

### خادم TURN (coturn)

يثبّته `deploy/install.sh` تلقائيًا:

- **التشغيل:** خدمة `coturn` في `docker-compose.yml` على شبكة المضيف. نظام ملفاتها للقراءة فقط، وكل صلاحيات Linux مُسقطة ما عدا `NET_BIND_SERVICE`.
- **السر:** يولّد المثبّت `TURN_SECRET` في `.env`. التطبيق يعطي كل مستخدم كلمة مرور مؤقتة (HMAC، صالحة ساعة).
- **الحماية:** يمنع الوصول إلى كل الشبكات الخاصة والداخلية (`denied-peer-ip`)، ولا يقبل relay عبر TCP، وله حصص لكل مستخدم.
- **TLS:** على المنفذ 5349، بنفس شهادة Caddy. يُعاد تشغيل coturn أسبوعيًا ليقرأ الشهادة المجددة (`/etc/cron.d/dzplay-turn`).

**المنافذ التي يجب فتحها** (يفتحها المثبّت في ufw، وافتحها أيضًا في جدار مزوّد VPS إن وُجد):

| المنفذ | البروتوكول | الاستخدام |
|---|---|---|
| 3478 | UDP + TCP | TURN |
| 5349 | TCP | TURN عبر TLS |
| 49160–49200 | UDP | نطاق relay للوسائط (كل مكالمة تستعمل منفذين تقريبًا؛ وسّعه بـ `TURN_MIN_PORT`/`TURN_MAX_PORT` إذا كثرت المكالمات المتزامنة) |

فحص سريع على الخادم:

```bash
cd /opt/dzplay/dzplay
docker compose logs --tail 30 coturn   # "TURN over TLS on port 5349" بعد صدور الشهادة
docker compose restart coturn          # بعد تغيير TURN_* في .env
```

### استهلاك البيانات (تقديري، مقيس في الاختبار)

- **مكالمة صوتية:** Opus مع FEC/DTX، نحو 8–40 kbit/s في كل اتجاه (أقل أثناء الصمت). الساعة تستهلك 4–18 MB لكل طرف.
- **مكالمة فيديو:** تبدأ بـ 600 kbit/s، وتصل 720p عند نحو 0.7–1.5 Mbit/s في كل اتجاه، وتنزل تلقائيًا إلى 480p/360p/240p عند الضعف. الساعة تستهلك 300–700 MB لكل طرف.
- **الخادم:** يمر عليه كل شيء، أي ضعف استهلاك الطرفين. مكالمة فيديو واحدة تستهلك نحو 1.5–3 Mbit/s دخولًا ومثلها خروجًا. مع 10 مكالمات فيديو متزامنة تحتاج نحو 30 Mbit/s في كل اتجاه. راقب حصة النقل الشهرية في خطة الـ VPS.

## 11. تطبيق أندرويد 2.0.0 وصفحة التحميل

- **صفحة التحميل:** `https://<نطاقك>/download`. فيها:
  - زر التحميل والإصدار والحجم وبصمة SHA-256؛
  - رمز QR؛
  - خطوات «مصادر غير معروفة»، وخطوات iPhone (Safari ← مشاركة ← إضافة إلى الشاشة الرئيسية).
- **التحديث داخل التطبيق:** عند الفتح يقارن التطبيق نسخته بـ `/api/app/version`، ويعرض «تحديث متوفر» مرة واحدة لكل إصدار.
- **ما يطلبه التطبيق من صلاحيات:** الإنترنت، الكاميرا، الميكروفون، توجيه الصوت (سماعة/مكبّر)، الإشعارات، والرنين على كامل الشاشة. لا شيء غير ذلك، ولا يُطلب إذن إلا عند الحاجة.
- **نشر إصدار جديد:**
  1. عدّل `appVersionCode`/`appVersionName` في `android/gradle.properties` وادفع. GitHub Actions يبني APK غير موقّع في فرع `android-build`.
  2. وقّعه بالمفتاح كما في الأسفل.
  3. ضعه في `static/download/dzplay.apk` وحدّث `static/download/version.json`.

### مفتاح التوقيع (keystore)

- يجب أن يبقى خارج المستودع وخارج مجلد الموقع، ولا يُرفع إلى GitHub أبدًا (`*.jks` في `.gitignore`).
- **احتفظ بنسختين خارج الخادم**، مثلًا USB مشفّر وخزنة كلمات مرور: ملف `dzplay-release.jks` وكلمة مروره (الاسم المستعار `dzplay`). بصمة الشهادة: `46:15:BE:65:23:30:C9:0A:C6:2C:C3:2C:E5:6B:0C:C0:CB:03:2B:8B:37:E7:13:86:0C:66:D0:A0:FA:EC:79:BF`.

```bash
zipalign -f -p 4 app-release-unsigned.apk aligned.apk

apksigner verify --print-certs DZPLAY.apk
```

## 12. الرنين والتطبيق مغلق (Firebase — اختياري)

**بدون Firebase:**
- ترن المكالمة عندما يكون التطبيق أو الموقع مفتوحًا.
- الموقع المثبّت على الشاشة (PWA) يتلقى إشعار «مكالمة واردة على DZPLAY» عبر Web Push.

**مع Firebase:** يرن تطبيق أندرويد على كامل الشاشة حتى وهو مغلق، مع أزرار «رد» و«رفض».

1. ادخل [console.firebase.google.com](https://console.firebase.google.com) ← **Add project** (عطّل Google Analytics إن أردت).
2. أضف تطبيق **Android**:
   - Package name: `io.dzplay.app`؛
   - حمّل ملف `google-services.json`.
3. في GitHub ← المستودع ← Settings ← Secrets and variables ← Actions ← **New repository secret**:
   - الاسم `GOOGLE_SERVICES_JSON`؛
   - القيمة: محتوى الملف كاملًا.

   ثم أعد بناء التطبيق (أي تعديل في `dzplay/android/` أو «Run workflow»)، ووقّعه وانشره (القسم 11).
4. في Firebase ← ⚙️ Project settings ← **Service accounts** ← **Generate new private key**، فيُحمَّل ملف JSON. **هذا سر: لا تضعه في git أبدًا.**
5. على الخادم:

```bash
cd /opt/dzplay/dzplay
mkdir -p secrets && chmod 700 secrets
nano secrets/firebase.json          # الصق محتوى ملف الخطوة 4
chown 10001 secrets secrets/firebase.json && chmod 600 secrets/firebase.json
echo 'FCM_SERVICE_ACCOUNT_FILE=/run/dzplay-secrets/firebase.json' >> .env
docker compose up -d app
```

الإشعارات لا تحمل اسم المتصل ولا رقمه ولا نص الرسائل، بل «مكالمة واردة على DZPLAY» أو «لديك رسالة جديدة» فقط.

> في أندرويد 14 فما فوق قد يمنع النظام الرنين على كامل الشاشة لتطبيقات من خارج المتجر. يظهر عندها إشعار عادي برنين، ويمكن السماح به من: إعدادات التطبيق ← الإشعارات ← «إشعارات بملء الشاشة».

## 14. الصور ومستودع Telegram (V5)

الملفات التي يرفعها المستخدمون (صورة الفكرة، صور المحادثات، ولاحقًا فيديوهات صنّاع المحتوى) تُحفظ في **قناة Telegram خاصة** ولا تُحفظ في الخادم. الخادم يمرّرها فقط:

1. يفحص الهاتف الصورة أولًا: نوعها الحقيقي، حجمها، أبعادها، ونموذج كشف المحتوى الإباحي على الجهاز. ثم يصغّرها.
2. يستقبلها الخادم في ذاكرة مؤقتة محدودة الحجم (tmpfs).
3. حاوية معزولة (`media-worker`) تعيد ترميز الملف وتحذف كل بياناته الوصفية (الموقع GPS، نوع الجهاز، التاريخ…). وتفحصه بنموذج الكشف نفسه.
4. يُرسل الناتج إلى قناة التخزين. نحتفظ بالمعرّف `file_id` فقط، ولا يُرسل أبدًا إلى أي مستخدم.
5. تُحذف كل الملفات المؤقتة. الملف المرفوض لا يصل إلى Telegram أبدًا.

### إنشاء القناتين (مرة واحدة)

**أ) قناة التخزين (Channel خاصة):**
1. في Telegram: ✏️ ← **قناة جديدة** ← اسم مثل «DZPLAY Storage» ← **خاصة**.
2. افتح إعدادات القناة ← **المشرفون** ← أضف بوت DZPLAY كمشرف. فعّل **نشر الرسائل** و**حذف رسائل الآخرين**.
3. لا تضف أي شخص آخر.

**ب) مجموعة الإشراف (Group خاصة):**
1. ✏️ ← **مجموعة جديدة** ← أضف البوت والمشرفين الذين تثق بهم فقط.
2. اجعل البوت **مشرفًا** في المجموعة.
3. كل صورة منشورة تصل إلى هنا مع أزرار: **حذف** / **حظر الناشر** / (**قبول** / **رفض** عند تفعيل الموافقة المسبقة). أي عضو في المجموعة يستطيع الضغط عليها، ويُسجَّل اسمه في سجل التدقيق.

**ج) معرفة رقم كل منهما:**
- أعد توجيه (Forward) أي رسالة من القناة إلى البوت **@userinfobot**. سيرد بالرقم، ويبدأ بـ `-100…`.
- للمجموعة: أضف **@userinfobot** إليها مؤقتًا. سيكتب رقمها. احذفه بعد ذلك.

**د) وضع الرقمين:**
- من اللوحة: **الإعدادات ← قنوات Telegram** (تُطبّق فورًا دون إعادة تشغيل).
- أو في `.env`:
  ```
  TELEGRAM_STORAGE_CHANNEL_ID=-100xxxxxxxxxx
  TELEGRAM_MODERATION_CHAT_ID=-100yyyyyyyyyy
  ```
  ثم نفّذ `docker compose up -d`.
- إذا تركت مجموعة الإشراف فارغة، تصل الإشعارات إلى محادثتك الخاصة مع البوت.

### كيف تعمل الصور
- **صورة مع الفكرة:**
  - صورة واحدة كل 24 ساعة (`IDEA_IMAGE_LIMIT_PER_24H`)، ويرى المستخدم عدًّا تنازليًا للصورة التالية.
  - تظهر فورًا، ثم تُراجَع من مجموعة الإشراف.
  - إذا فعّلت `IDEA_IMAGE_REQUIRE_APPROVAL`، لا تظهر الفكرة لغير صاحبها حتى تضغط «قبول».
- **صورة في محادثة:**
  - متاحة بعد أن يرد الطرف الآخر.
  - تصل مموّهة مع «اضغط للعرض».
  - بعد فتحها تبقى `CHAT_IMAGE_TTL_AFTER_VIEW` ثانية (120 افتراضيًا)، ثم تختفي عند الطرفين وتظهر «انتهت صلاحية الصورة».
  - الصورة التي لا تُفتح تُحذف بعد `CHAT_IMAGE_UNOPENED_TTL`.
  - نسخة التخزين تُحذف من Telegram بعد مهلة إبلاغ قصيرة (`CHAT_IMAGE_REPORT_GRACE`، 10 دقائق). خلال هذه المهلة لا يراها أحد.
  - إذا أُبلغ عنها تُحفظ كدليل وتصل إلى مجموعة الإشراف.
  - صور المحادثات لا تُرسل إلى الإشراف إلا عند البلاغ.
  - `CHAT_IMAGE_ARCHIVE=false` افتراضيًا. إذا غيّرته يجب ذكر ذلك في سياسة الخصوصية.
  - في تطبيق أندرويد تُمنع لقطة الشاشة أثناء عرض الصورة (`CHAT_IMAGE_FLAG_SECURE`).
- **البلاغات:**
  - إذا أبلغ `REPORT_AUTO_HIDE_THRESHOLD` أشخاص مختلفين (3 افتراضيًا)، تُخفى الصورة حتى تقرر.
  - سبب «محتوى يخص قاصرًا» يُخفي فورًا ويطلب تأكيدك: زر **🚨 تأكيد** يحذف المحتوى، ويحظر الناشر، ويحفظ نسخة الدليل في قناة التخزين `MEDIA_EVIDENCE_RETENTION_DAYS` يومًا.
  - لا يوجد نموذج يكشف القاصرين آليًا، فالمراجعة البشرية هي الأساس.

### حدود يجب معرفتها
- Telegram لا يسمح للبوت بحذف رسالة أقدم من 48 ساعة. لذلك:
  - صور المحادثة تُحذف دائمًا خلال المهلة، لأن الحد الأقصى لعدم الفتح 46 ساعة.
  - صورة فكرة تُحذف بعد أيام: يتوقف التطبيق عن الوصول إليها فورًا، لكن قد تبقى في القناة الخاصة، ويمكنك حذفها يدويًا من القناة.
- كل الحدود (الأحجام، العدد في الساعة، العتبات، تفعيل الفحص على الخادم) تُعدّل من اللوحة دون إعادة تشغيل.

### المتغيرات الجديدة في `.env` (V5 — الصور)
- **قنوات Telegram:** `TELEGRAM_STORAGE_CHANNEL_ID` `TELEGRAM_MODERATION_CHAT_ID`
- **الرفع والمعالجة:**
  - المعالجة: `UPLOAD_TMP_DIR` `UPLOAD_TMP_MAX_MB` `UPLOAD_QUEUE_MAX` `MEDIA_WORKER` `MEDIA_WORKER_TIMEOUT` `MEDIA_FFMPEG_MEM_MB` `TELEGRAM_STORE_MAX_MB`
  - حدود الملفات: `UPLOADS_PER_HOUR` `UPLOAD_IMAGE_TYPES` `UPLOAD_VIDEO_TYPES` `UPLOAD_IMAGE_MAX_MB` `UPLOAD_IMAGE_MIN_SIDE` `UPLOAD_IMAGE_MAX_SIDE`
  - على الهاتف: `DEVICE_IMAGE_MAX_SIDE` `DEVICE_IMAGE_QUALITY`
- **كشف المحتوى:** `DEVICE_NSFW_CHECK` `SERVER_NSFW_CHECK` `NSFW_BLOCK_THRESHOLD` `NSFW_SEXY_THRESHOLD` `NSFW_VIDEO_FRAMES` `CAPTION_BLOCK_CATEGORIES`
- **صور الأفكار:** `IDEA_IMAGES_ENABLED` `IDEA_IMAGE_LIMIT_PER_24H` `IDEA_IMAGE_REQUIRE_APPROVAL`
- **صور المحادثات:** `CHAT_IMAGES_ENABLED` `CHAT_IMAGE_TTL_AFTER_VIEW` `CHAT_IMAGE_UNOPENED_TTL` `CHAT_IMAGE_PER_HOUR` `CHAT_IMAGE_REPORT_GRACE` `CHAT_IMAGE_ARCHIVE` `CHAT_IMAGE_FLAG_SECURE`

**قياس الأداء:** فحص الخادم يستغرق نحو 8–30 ms للصورة على نواة واحدة. النموذج يستهلك نحو 100 MB من الذاكرة في حاوية المعالجة فقط. معالجة صورة كاملة تستغرق نحو 0.3 ثانية.

## 15. الدعم والنجمة الزرقاء (V5)

### الدعم
- يفتح المستخدم تذكرة من **حسابي ← الدعم والمساعدة**. الأنواع: تقنية، الحساب، التوثيق، الدفع، بلاغ، اقتراح، أخرى.
- كل تذكرة تأخذ رقمًا (#1001…).
- عند فتح التذكرة:
  - تصل رسالة إلى `SUPPORT_INBOX_EMAIL`. عنوانها يحمل الرقم. Reply-To هو بريد المستخدم، والنص يحتوي معرّفه العام فقط.
  - يصلك إشعار في بوت Telegram.
- طريقتان للرد:
  - **من اللوحة ← الدعم:** يظهر الرد فورًا في «تذاكري»، ويصل للمستخدم بريد ينبّهه.
  - **من Gmail مباشرة:** الرد يصل إلى بريد المستخدم، لكنه لا يُسجَّل داخل التطبيق.
- الحالات: مفتوحة / تم الرد / مغلقة.
- الحدود قابلة للتعديل من **الإعدادات**: `SUPPORT_TICKETS_PER_DAY` و`SUPPORT_MESSAGES_PER_HOUR`.

### النجمة الزرقاء
- معناها: **حساب رسمي موثوق** داخل DZPLAY. **ليست تحققًا من الهوية**، ولا تُطلب أي وثيقة أو معلومة شخصية. يمكنك سحبها في أي وقت.
- **الشروط** (تُعدّل من الإعدادات): `VERIFY_MIN_POSTS` `VERIFY_MIN_LIKES` `VERIFY_MIN_ACCOUNT_AGE_DAYS`، وبدون مخالفات. يرى المستخدم أشرطة تقدّم، وزر الطلب لا يعمل حتى تكتمل الشروط.
- **إعداد الدفع:** من **اللوحة ← إعدادات الدفع**:
  - العملة (مثل USDT).
  - الشبكة: TRC20 / BEP20 / ERC20 / Polygon / Arbitrum / Solana / TON / BTC / أخرى.
  - عنوان المحفظة.
  - رابط المستكشف (اختياري، يحتوي `{txid}`، وله قيمة افتراضية لكل شبكة).
  - ملاحظة.
  
  إذا تركت المحفظة فارغة، يرى المستخدمون «الدفع غير متاح حاليًا» ولا يمكنهم الطلب.
- **ما يراه المستخدم:** رمز QR، وزر نسخ العنوان، وتحذير واضح من الشبكة الخاطئة. المبلغ حر (`PAYMENT_MIN_AMOUNT` اختياري). يُدخل المستخدم المبلغ ورقم العملية TXID، ويُفحص شكل الرقم حسب الشبكة. لا يُقبل TXID استُعمل في طلب آخر.
- **المراجعة:**
  - افتح رابط المستكشف وتأكد من المبلغ والعنوان.
  - من **اللوحة ← التوثيق** اختر: **قبول**، أو **رفض** مع ذكر السبب، أو **يحتاج تصحيحًا** (يعدّل المستخدم طلبه ويعيد إرساله).
  - أو استعمل أزرار رسالة البوت.
  - كل قرار يُسجّل في سجل التدقيق، ويُبلَّغ به المستخدم داخل التطبيق وعلى بريده.
- **منح أو سحب يدوي:** من **صفحة المستخدم في اللوحة**.
- **أين تظهر النجمة:** في الملف الشخصي، والأفكار، وتعليقات Reels، والبحث، والمحادثات المباشرة. **لا تظهر أبدًا في المحادثات المجهولة**، حتى بعد كشف الهوية.
- لا يوجد أي طريق للمستخدم لتعديل التوثيق بنفسه، والاختبارات تتحقق من ذلك.

## 16. استوديو صنّاع المحتوى وتحقيق الدخل و«أموالي» (V5)

### استوديو DZPLAY
- متاح لأصحاب **النجمة الزرقاء فقط**. يجده المستخدم في **حسابي ← استوديو DZPLAY**.
- النافذة تشبه المحادثة:
  1. 📎 لاختيار فيديو، ثم معاينة.
  2. وصف للفيديو.
  3. خيار «إظهار اسمي على الفيديو» أو «نشر بدون اسم».
  4. خيار «عرضه في ملفي الشخصي» أو «عدم عرضه».
  5. إرسال، مع شريط تقدّم ورسائل حالة: قيد المراجعة ← نُشر، أو رُفض مع السبب.
- **الفحص:**
  - يفحص الهاتف نوع الفيديو ومدته وبعض لقطاته.
  - يعيد الخادم ترميز الفيديو إلى 720p وأقل من 18MB، ويحذف بياناته الوصفية، ويفحص لقطاته، ثم يحفظه في قناة التخزين.
- **الحدود (من الإعدادات):** `CREATOR_REEL_LIMIT_PER_24H` (1 مع عدّ تنازلي)، و`REJECTED_COUNTS_TOWARD_LIMIT`، و`CREATOR_REEL_MIN/MAX_SECONDS`، و`CREATOR_REEL_MAX_MB`، و`CREATOR_UPLOAD_CHAT_TTL` (مدة بقاء الفيديو في نافذة الاستوديو؛ الـReel نفسه يبقى منشورًا).
- **المراجعة:** `REELS_REQUIRE_APPROVAL=true`. كل فيديو يصل إلى مجموعة الإشراف مع زرّي **✅ قبول** و**❌ رفض** وزر **⛔ حظر الناشر**. يمكن المراجعة أيضًا من **اللوحة ← الإشراف على الوسائط**.
- **بعد النشر:**
  - يدخل الفيديو في Reels العشوائية.
  - **مع الاسم:** يظهر الاسم والنجمة، ويفتح الملف الشخصي عند الضغط.
  - **بدون اسم:** يبدو كمحتوى المنصة، ولا يمكن عرضه في الملف الشخصي أبدًا.
  - يستطيع صاحبه تغيير الخيارين أو حذف الفيديو.
- **البلاغ عن فيديوهات الصنّاع:** متاح بزر 🏳. تُطبّق عليه قواعد الإخفاء التلقائي نفسها. فيديوهات المنصة لا تُبلَّغ عبر هذا الزر.

### تحقيق الدخل
- يظهر للموثّقين في **حسابي ← تحقيق الدخل**.
- **الشروط:** `MONETIZE_MIN_REELS` و`MONETIZE_MIN_LIKES`، مع أشرطة تقدّم.
- **الطلب:** نوع المحتوى، وبريد استلام الأرباح، والموافقة على الشروط. البريد الافتراضي هو بريد الحساب؛ أي بريد آخر يُؤكَّد برمز يُرسل إليه.
- **المراجعة:** من **اللوحة ← تحقيق الدخل** أو من زرّي البوت. القرار يُسجّل في سجل التدقيق.

### «أموالي»
- تظهر بعد قبول طلب تحقيق الدخل.
- يرى المستخدم: الرصيد، وإجمالي الأرباح، والسجل. **القراءة فقط**؛ لا يوجد أي طريق لتعديلها من التطبيق.
- **السجل غير قابل للتعديل:**
  - كل حركة قيد جديد، والرصيد هو مجموع القيود.
  - لتصحيح خطأ استعمل **«إلغاء قيد»**: ينشئ قيدًا معاكسًا، ولا يُلغى القيد مرتين.
  - لا يوجد حذف ولا تعديل.
- **إضافة أرباح:** من **صفحة المستخدم في اللوحة ← الأرباح**: نوع «أرباح» + المبلغ + ملاحظة.
- **الدفع:**
  1. أرسل **الظرف الأحمر** إلى بريد المستخدم المسجّل للأرباح، من تطبيقك خارج DZPLAY.
  2. سجّل قيد «دفعة»: المبلغ والتاريخ وملاحظة.
  3. يُخصم المبلغ (لا يمكن أن يتجاوز الرصيد)، ويصل للمستخدم إشعار وبريد: «تم إرسال أرباحك إلى بريدك عبر الظرف الأحمر، ادخل إلى المنصة لاستلامها.»

## 17. أقسام لوحة القيادة الجديدة (V5)
- **الإشراف على الوسائط:** صور الأفكار، وفيديوهات الصنّاع، وصور المحادثات المبلّغ عنها، مع معاينة.
  - التصفية: بانتظار الموافقة / منشور / مبلّغ عنه / مرفوض بالفحص / محذوف.
  - الإجراءات: قبول / إبقاء / حذف / حذف + حظر / قاصر (حذف + حظر + حفظ دليل).
  - تتحدث رسالة Telegram المقابلة تلقائيًا.
- **التوثيق والدفع:** إعدادات الدفع (العملة / الشبكة / المحفظة / المستكشف / ملاحظة)، وطلبات النجمة مع رابط المستكشف، وقرار قبول / رفض / تصحيح. «الكل» يعرض سجل الدفع كاملًا.
- **الأرباح:** طلبات تحقيق الدخل، ودفتر الأرباح لكل مستخدم: إضافة أرباح، أو دفعة الظرف الأحمر، أو تسوية، أو إلغاء قيد.
- **الدعم:** التذاكر حسب الحالة، والبحث برقم التذكرة (#1001) أو بالمعرّف العام، والرد، والإغلاق.
- **الإعدادات:** كل الحدود والشروط مجمّعة حسب القسم. «حفظ» يُطبّق فورًا على كل الخوادم دون إعادة تشغيل. «افتراضي» يعيد القيمة الموجودة في `.env`. كل تغيير يُسجَّل.
- **صفحة المستخدم:** تضم الآن النجمة (منح / سحب)، وطلبات التوثيق، والوسائط المرفوعة، وفيديوهات الاستوديو، والتذاكر، وتحقيق الدخل، وزر الأرباح.

## 18. السياسات وحذف الحساب
- الصفحات العامة: `/policies` (فهرس)، و`/policies/privacy`، و`/policies/terms`، و`/policies/guidelines`، و`/policies/verification`، و`/policies/earnings`.
  - كل صفحة تبدأ بمبدأ DZPLAY.
  - الأرقام (مدة الصور، الأرشفة، مدد الاحتفاظ، الشروط) تُقرأ من الإعدادات الحالية، فتبقى السياسة مطابقة لما يعمل فعلًا.
  - روابطها موجودة في: حسابي، وصفحة التسجيل، و`/download`.
- تحديث سياسة الخصوصية (الإصدار 5) يظهر مرة واحدة لكل مستخدم.
- **حذف حسابي** (حسابي ← حذف حسابي):
  - يطلب كلمة المرور. حسابات Google تكتب «حذف حسابي» بدلًا منها.
  - يحذف كل البيانات المذكورة في سياسة الخصوصية، ويحذف الوسائط من قناة التخزين.
  - يُسجَّل في سجل التدقيق بالمعرّف العام فقط.
