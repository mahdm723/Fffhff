تقلّص سطح الهجوم:
- **لا مكالمات ولا TURN:** حُذفت خدمة coturn ومسارات `/api/calls` و`/api/turn` ورسائل `call.*` في WebSocket (لم يبق إلا `ping` و`typing`). `harden.sh close-turn` يغلق منافذ 3478/5349/49160-49200 القديمة. `Permissions-Policy: camera=(), microphone=()` في كل استجابة.

- **البيانات القديمة:** تُصدَّر مشفّرة (AES-256، `BACKUP_PASSPHRASE`) دون أن تلمس القرص مكشوفة، ثم تُحذف في معاملة واحدة لا تتم إلا إن طابقت بصمة SHA-256 ما حُفظ (`deploy/v6-cleanup.sh`، `tests/test_v6_cleanup.py`).

2. `add-user NAME` ينشئ مستخدمًا بصلاحية sudo وينسخ إليه مفتاح root.
3. `apply` يرفض إن لم يجد:
   - مستخدم sudo لديه مفتاح؛
   - دخولًا ناجحًا بالمفتاح لهذا المستخدم في سجل SSH خلال آخر ساعة؛
   - أن تكتب بنفسك «دخلت بالمفتاح» (لا يعمل من سكربت).
4. بعدها: نسخة احتياطية → ملف `00-dzplay-ssh.conf` → `sshd -t` → يتحقق من القيم **الفعلية** → مؤقّت يعيد كل شيء تلقائيًا بعد 10 دقائق → إعادة تحميل SSH (الجلسات المفتوحة تبقى).
5. تجرّب من نافذة Termux جديدة، ثم `confirm`؛ أو `rollback` فورًا.

جُرّب على sshd حقيقي:
- كل حالات الرفض؛
- بعد التطبيق: المفتاح يعمل، root مرفوض، ولا يُعرض أي أسلوب غير المفتاح؛
- `rollback` و`confirm` والاسترجاع التلقائي بالمؤقّت.

**لم أطبّقه على خادمك:** الخطوات في قسم «أوامر الخادم» تنفّذها أنت بعد التأكد من مفتاح Termux.

**حدود معروفة:**

- **كشف القُصّر:** لا يوجد نموذج يكشف القُصّر بشكل موثوق. الحماية هي بلاغ «محتوى يخص قاصرًا» (إخفاء فوري + مراجعة + حفظ الدليل) والمراجعة البشرية.
- **حذف رسائل التخزين:** Telegram لا يسمح للبوت بحذف رسالة أقدم من 48 ساعة. التطبيق ينسى الملف فورًا (لا `file_id` ولا نسخة مؤقتة)، وأي بقايا تُحذف يدويًا من القناة عند الحاجة.
- **مجموعة الإشراف:** كل عضو فيها يستطيع ضغط الأزرار، فأبقها لمشرفين تثق بهم فقط.
- **المدفوعات:** التحقق يدوي عبر رابط المستكشف، ولا شيء آلي أو مُودَع لدى المنصة.
- **صور Docker:** لم تُفحص بأداة مثل trivy هنا. التحديث يتم بإعادة تشغيل أمر التثبيت (يسحب أحدث الصور).

## 2. تفاصيل الإصلاحات

**F1 — مدخلات ffmpeg.** صار `probe` يرفض أي حاوية غير الفيديو الحقيقية (mp4/mov/mkv/webm/avi/flv/ts)، فتُرفض صيغ hls وconcat وغيرها قبل أن يعمل ffmpeg. كل تشغيل لـ ffprobe/ffmpeg يمرّ الآن بـ `-protocol_whitelist file`، فلا http ولا tcp. الأوامر كانت أصلًا قوائم وسائط بلا shell، بمهلة زمنية، وبمستخدم غير root. الرفع ممكن فقط من محادثة المشرف في Telegram، لذا كان الخطر الفعلي محدودًا، لكنه أُغلق كدفاع إضافي. (`app/services/media.py`)

**F2 — SSRF عبر Web Push.** يُقبل الرابط فقط إن كان `https` على خدمة إشعارات معروفة: Google FCM وMozilla وMicrosoft WNS وApple. يُرفض أي منفذ غير 443، وأي بيانات دخول داخل الرابط، وأي عنوان IP أو اسم داخلي. القائمة قابلة للتعديل بالمتغير `PUSH_ALLOWED_HOSTS`. يُطبَّق نفس الفحص عند الإرسال أيضًا: أي اشتراك قديم مخالف يُحذف ولا يُتصل به. (`app/services/push.py`)

**F3 — النسخ الاحتياطي.**
- `deploy/backup.sh` يأخذ `pg_dump` ونسخة من `.env`، ثم يشفّرهما بـ GnuPG (AES-256 مع حماية السلامة) بالمتغير `BACKUP_PASSPHRASE`.
- يتحقق بعد الكتابة بفك التشفير وقراءة المحتوى بـ `pg_restore --list`.
- يحتفظ بآخر `BACKUP_KEEP` نسخة، ويمكنه النسخ خارج الخادم عبر rclone.
- `deploy/restore.sh` يستعيد النسخة داخل معاملة واحدة، مع تأكيد قبل التنفيذ.
- المثبّت يولّد كلمة سر التشفير مرة واحدة، ويضيف مهمة cron يومية الساعة 03:17، ويأخذ نسخة أولى فورًا.
- **تم اختبار الدورة كاملة فعليًا:**
  - 3 نسخ → بقيت 2، بصلاحية 600 داخل مجلد بصلاحية 700.
  - لا يظهر أي نص مقروء داخل الملف.
  - كلمة السر الخاطئة رُفضت.
  - حذفنا المستخدمين والأفكار ثم استعدناها، فعادت البيانات كما كانت وبقيت سلسلة سجل الإدارة سليمة.

- فحص إعدادات SSH. مع الخيار `--ssh-keys-only` يوقف الدخول بكلمة المرور، **فقط إذا وُجد مفتاح SSH مسجّل** حتى لا تُقفل خارج خادمك.
- جعل `.env` مقروءًا لـ root فقط.

## 4. ما يحتاج قرارك أنت

1. **F10 — ألغِ رموز البوت القديمة (مهم جدًا).** سجل git العام لهذا المستودع يحتوي 3 رموز من `bot.py` القديم (تبدأ بـ `8108703711:` و`8527245679:` و`8588167836:`).
   - افتح @BotFather ← `/mybots` ← اختر البوت ← **API Token** ← **Revoke current token**، لكل بوت منها.
   - إلغاء الرمز هو الحل الحقيقي، فالمستودع عام وقد يكون نُسخ.
   - (إعادة كتابة سجل git لحذفها ممكنة لكنها مدمّرة لكل نسخ المستودع، ولم أفعلها دون إذنك.)
2. **F11 — غيّر رمز البوت الحالي.** أُرسل في المحادثة، لذا:
   - في @BotFather: **Revoke** ثم انسخ الرمز الجديد.
   - ضعه في `.env` على الخادم (`TELEGRAM_BOT_TOKEN=`).
   - نفّذ `docker compose up -d app`.
   - هذا الرمز لم يُكتب في الكود ولا في git.
3. **احفظ `BACKUP_PASSPHRASE` خارج الخادم** (مدير كلمات مرور). بدونه لا يمكن فك أي نسخة. يفضَّل أيضًا نسخ النسخ خارج الخادم (`BACKUP_RCLONE_REMOTE`)، فإن ضاع الخادم ضاعت النسخ المحلية معه.
4. **شغّل `harden.sh`**، ثم اتبع خطوات `ssh-harden.sh` (V5) لجعل SSH بالمفاتيح فقط.
5. **(اختياري)** `ADMIN_IP_ALLOWLIST`: يقصر اللوحة على شبكتك فقط. يفيد إذا كان عنوان IP منزلك ثابتًا.
6. **(اختياري)** اجعل المستودع **خاصًا** على GitHub. لا أسرار فيه الآن، لكن ذلك يقلل المعلومات المتاحة لأي مهاجم.
7. **إعادة التشغيل بعد تحديثات النواة**: التحديثات التلقائية لا تعيد تشغيل الخادم بنفسها. تحقق من وجود `/var/run/reboot-required` من حين لآخر.
