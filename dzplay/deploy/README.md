# تشغيل DZPLAY على خادم VPS وتجربته على هاتفك

الدليل كله أمر واحد تنسخه وتلصقه في الخادم. السكربت يثبّت كل شيء بنفسه: Docker، قاعدة البيانات PostgreSQL، Redis، شهادة HTTPS مجانية، ومفاتيح سرية جديدة.

---

## قبل البدء

| المطلوب | التفاصيل |
|---|---|
| نظام الخادم | Ubuntu 20.04 أو أحدث، أو Debian 11 أو أحدث |
| الذاكرة | 1 GB RAM على الأقل |
| المنافذ | 80 و 443 مفتوحة في لوحة تحكم مزوّد الخادم (Firewall / Security Group) |
| الدخول | اسم المستخدم (عادة `root`) وكلمة المرور أو مفتاح SSH |

> لا ترسل كلمة مرور الخادم لأي أحد، بما في ذلك في المحادثة. أنت من يشغّل الأمر بنفسك.

---

## الخطوة 1 — الدخول إلى الخادم

- **من الكمبيوتر (Windows / Mac / Linux):** افتح Terminal أو PowerShell واكتب:
  ```
  ssh root@IP_الخادم
  ```
- **من الهاتف (Android):** ثبّت تطبيق **Termux** أو **JuiceSSH**، ثم نفس الأمر.

---

## الخطوة 2 — أمر التثبيت

انسخ هذا السطر كاملًا والصقه في الخادم ثم اضغط Enter:

```bash
curl -fsSL https://raw.githubusercontent.com/mahdm723/Fffhff/claude/github-access-check-c1exvo/dzplay/deploy/install.sh | sudo bash
```

يستغرق 3 إلى 5 دقائق في المرة الأولى. في النهاية يظهر لك رابط مثل:

```
Open on your phone:   https://203-0-113-10.sslip.io
```

هذا رابط تطبيقك. لا تحتاج شراء نطاق (دومين): السكربت يستخدم عنوانًا مجانيًا مبنيًا على IP الخادم مع شهادة HTTPS حقيقية.

**إذا كان لديك نطاق خاص** (مثلًا `chat.example.com`): وجّه سجل `A` الخاص به إلى IP الخادم، ثم شغّل:
```bash
curl -fsSL https://raw.githubusercontent.com/mahdm723/Fffhff/claude/github-access-check-c1exvo/dzplay/deploy/install.sh | sudo DOMAIN=chat.example.com bash
```

## الخطوة 3 — تثبيت التطبيق على هاتفك

DZPLAY تطبيق ويب قابل للتثبيت (PWA): يظهر بأيقونة على الشاشة الرئيسية ويفتح بملء الشاشة مثل أي تطبيق.

**Android (Chrome):**
1. افتح الرابط في Chrome.
2. اضغط القائمة **⋮** في الأعلى.
3. اختر **تثبيت التطبيق** أو **إضافة إلى الشاشة الرئيسية**.

**iPhone (Safari):**
1. افتح الرابط في Safari.
2. اضغط زر **المشاركة** (المربع والسهم).
3. اختر **إضافة إلى الشاشة الرئيسية**.

لتفعيل إشعارات الرسائل الجديدة: افتح التطبيق ← **حسابي** ← فعّل **إشعارات الرسائل الجديدة**. على iPhone تعمل الإشعارات فقط بعد إضافة التطبيق للشاشة الرئيسية (iOS 16.4 أو أحدث).

---

## تطبيق أندرويد (APK) لمشاركته مع الأصدقاء

بعد تحديث الخادم يصبح ملف التطبيق متاحًا على:

```
https://<رابط تطبيقك>/download/dzplay.apk
```

- أرسل هذا الرابط لأصدقائك، أو من داخل التطبيق: **حسابي ← مشاركة تطبيق DZPLAY**.
- عند فتح الموقع من متصفح أندرويد يظهر زر **تحميل تطبيق أندرويد** في صفحة الدخول.
- عند التثبيت قد يطلب الهاتف السماح بـ **التثبيت من مصادر غير معروفة** للمتصفح أو لتطبيق الملفات. هذا طبيعي لأن التطبيق ليس من متجر Google Play.

التطبيق يفتح DZPLAY بملء الشاشة بأيقونته الخاصة، ولا يحتاج Chrome ولا أي متصفح. المحتوى يأتي من خادمك، لذلك **كل تحديث للخادم يصل لكل من ثبّت التطبيق تلقائيًا** دون ملف APK جديد. تحتاج APK جديدًا فقط إذا غيّرت عنوان الموقع (النطاق).

> التطبيق مرتبط بعنوان `72-61-147-28.sslip.io`. إذا انتقلت إلى نطاق خاص، غيّر `appHost` في `android/gradle.properties` وأعد البناء.

## لوحة التحكم

اللوحة على **مسار سري** يولّده المثبّت، وتحتاج **حساب مشرف + رمز تحقق من تطبيق المصادقة**:

```bash
cd /opt/dzplay/dzplay
docker compose exec app python -m app.admin_cli create-admin owner   # مرة واحدة: كلمة مرور ثم رمز QR
grep ADMIN_PATH .env                                                  # عنوان اللوحة: https://<رابطك><ADMIN_PATH>
```

امسح رمز QR بتطبيق Google Authenticator أو Microsoft Authenticator، ثم ادخل من الهاتف أو الكمبيوتر. الشرح الكامل في [docs/ADMIN_GUIDE.md](../docs/ADMIN_GUIDE.md):
- المستخدمون والمحتوى.
- التحكم في التفاعل ومكتبة التعليقات.
- بوت Telegram.
- النسخ الاحتياطي.
- التحصين.

**بوت Telegram (رفع الفيديوهات والصور):** اللوحة ← **الأمان والنظام** ← **بوت Telegram**. الصق رمز البوت ورقم محادثتك ورمز التحقق، ثم اضغط **حفظ وربط البوت**. البديل من الخادم: `sudo /opt/dzplay/dzplay/deploy/telegram-setup.sh`.

**حماية المستخدمين:** في تبويب **البلاغات ← رصد تلقائي** تظهر الرسائل والتعليقات التي رصدها النظام (تهديد، ابتزاز، تحرش، سب، طلب أرقام أو حسابات). لإضافة كلماتك الخاصة للرصد، أضف في `.env` ثم أعد التشغيل:
```bash
MODERATION_EXTRA_WORDS=كلمة1,كلمة2,عبارة كاملة,بداية*
```

## الخطوة 4 — التجربة

تحتاج حسابين لأن الرسالة تذهب لشخص آخر:
1. سجّل حسابًا على هاتفك.
2. سجّل حسابًا ثانيًا على جهاز آخر، أو في نافذة خاصة (Incognito) في المتصفح.
3. اكتب رسالة من الحساب الأول ← تصل للثاني ← رد ← تستمر المحادثة.

> حد الأمان الافتراضي هو حسابان جديدان لكل شبكة (IP) كل 4 ساعات. إذا أردت إنشاء حسابات تجريبية كثيرة من نفس الشبكة، أضف IP شبكتك إلى `TRUSTED_IPS` (انظر "تعديل الإعدادات" بالأسفل).

## أوامر مفيدة

```bash
cd /opt/dzplay/dzplay
docker compose ps                                       # حالة الخدمات
docker compose logs -f app                              # سجل التطبيق المباشر
docker compose restart app                              # إعادة التشغيل
docker compose down                                     # إيقاف (البيانات تبقى)
docker compose up -d                                    # تشغيل مجددًا
docker compose exec app python -m app.admin_cli stats   # إحصائيات
docker compose exec app python -m app.admin_cli reports # البلاغات
```

### تعديل الإعدادات
الإعدادات في `/opt/dzplay/dzplay/.env` (حدود الرسائل، مدة الحظر، مدة حذف الرسائل…). بعد أي تعديل:
```bash
cd /opt/dzplay/dzplay && nano .env && docker compose up -d
```

## النسخ الاحتياطي والتحصين

- **النسخ الاحتياطي:** يومي ومشفّر في `/var/backups/dzplay` (يضبطه المثبّت). **احفظ كلمة السر خارج الخادم:** `grep BACKUP_PASSPHRASE /opt/dzplay/dzplay/.env`
  - نسخة فورية: `sudo /opt/dzplay/dzplay/deploy/backup.sh`
  - استعادة: `sudo /opt/dzplay/dzplay/deploy/restore.sh <الملف>`
- **التحصين:** `sudo /opt/dzplay/dzplay/deploy/harden.sh` يضبط جدارًا ناريًا وfail2ban وتحديثات أمنية تلقائية. بعد إضافة مفتاح SSH، أضف `--ssh-keys-only`.
- أو ثبّت مع التحصين من البداية: `curl … | sudo HARDEN=1 bash`.

## حل المشاكل

| المشكلة | الحل |
|---|---|
| `Port 80 is already used` | برنامج آخر يستخدم المنفذ، غالبًا nginx أو apache. أوقفه: `systemctl stop nginx && systemctl disable nginx` ثم أعد الأمر. |
| `Not reachable from outside` | افتح المنفذين 80 و 443 في لوحة تحكم مزوّد الخادم، ثم أعد الأمر. |
| الشهادة لم تصدر | راجع السجل بالأمر `docker compose logs caddy`. إذا كان السبب حدود sslip.io، استخدم نطاقك الخاص (`DOMAIN=...`). |
| تجربة سريعة بدون HTTPS | أضف `MODE=http` قبل `bash`. للتجربة فقط: لا يمكن تثبيت التطبيق على الهاتف ولا تعمل الإشعارات. |
| بوت تيليجرام على نفس الخادم | لا يتأثر. DZPLAY يعمل داخل Docker في `/opt/dzplay` ولا يلمس ملفات البوت. |

## الأمان

- الأسرار تُولَّد عشوائيًا عند التثبيت وتُحفظ في `.env` بصلاحية قراءة لـ root فقط. لا ترفع هذا الملف إلى GitHub.
- قاعدة البيانات و Redis غير مكشوفين على الإنترنت؛ فقط المنفذان 80 و 443 عبر Caddy.
- لا تُسجَّل عناوين IP في سجلات الخادم.
- يُنصح بالدخول للخادم بمفتاح SSH بدل كلمة المرور (`deploy/harden.sh --ssh-keys-only`).
- الحاويات مُحصّنة: نظام ملفات للقراءة فقط، بلا صلاحيات Linux، ومستخدم غير root.
- تقرير الفحص الأمني الكامل: [docs/SECURITY_AUDIT.md](../docs/SECURITY_AUDIT.md).
